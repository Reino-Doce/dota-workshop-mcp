# Build 2439: internal Source1Import

**Source1Import refers to the Source 1 asset conversion tool hosted internally
by `dota2.exe`. It was removed after build 2440.** This workflow targets build
2439. The similarly named community project `kristiker/source1import` is a
different tool and is mentioned here only to disambiguate the name.

## MCP endpoints

MCP does not expose the internal conversion operation. Use these endpoints for
setup and validation, and the matching tools/editor for conversion:

| Endpoint | Usage |
|---|---|
| `dota_select_installation` | Select the build-2439 `installationId`, or `activeVersion:"2439"` when unambiguous; set its `vconPort`. |
| `addon_info` | Supply the isolated `addon` to inspect its maps and settings. |
| `dota_launch` | Supply `addon` and `map`, and inspect `dryRun:true` before starting the historical tools session. |
| `addon_compile_content` | Supply `projectRoot` and inspect `dryRun:true` before compiling generated Source 2 sources with build 2439. |
| `vconsole_logs`, `vconsole_tail` | Read or wait for bounded engine import/resource messages using `after`, `pattern` and `limit`; standalone compiler output comes from the compile call itself. |

Read the [staging and fidelity procedure](staging-and-fidelity.md)
for source dependencies and validation gates.

## Select the source and destination

Confirm `game/dota/steam.inf` identifies `ClientVersion=2439`,
`SourceRevision=4163623`, `VersionDate=Oct 03 2017`.
[Pinned metadata](https://github.com/SteamTracking/GameTracking-Dota2/blob/b0c2741e6f27ec8dbf7c64b5dd16b09b744e8b43/game/dota/steam.inf)

Keep a writable Source 1 extraction in `ROOT/game/dota_s1_legacy/`, with its
`gameinfo.txt` and original relative paths. Preserve MDL sidecars and animation
dependencies, VMT/VTFs, PCFs and children, sounds and referencing scripts from
the same snapshot. Keep the original BSP and a recovered VMF separately.

Create or select an isolated addon under both `ROOT/content/dota_addons/<addon>`
and `ROOT/game/dota_addons/<addon>`. Keep the extraction outside the Source 2
base-content tree and separate from immutable archives or another build's outputs.

## Configure the internal converter

The build's [gameinfo.gi](https://github.com/SteamTracking/GameTracking-Dota2/blob/b0c2741e6f27ec8dbf7c64b5dd16b09b744e8b43/game/dota/gameinfo.gi#L188)
contains the `Source1Import` block. Preserve its options, changelist history,
repeated `oldchangelist` keys and depot paths.

1. Check sessions sharing `ROOT/game/dota/gameinfo.gi`; coordinate any change
   before editing. Back up the complete file independently and record its hash.
2. Change only the source mapping needed for the staged mod. For the layout above:

   ```text
   "importmod" "dota_s1_legacy"
   "importdir" "..\dota_s1_legacy"
   ```

   This pair belongs inside the existing block. Confirm its path resolution in
   importer logs or file accesses during a small conversion probe.
3. Record the diff and applied-file hash. `createStaticOverlays=1` converts overlay
   entities to static nodes; account for that change in the map audit.
4. After closing the session using the temporary mapping, restore the backup
   only if the file still matches the applied hash. Reconcile concurrent edits
   instead of overwriting them, then verify the original hash was restored.

## Import through the matching tools

Launch the [historical tools session](../dota2/launch.md#build-2439)
with the isolated addon and capture a fresh log boundary. For a map, open the
prepared VMF in Hammer using `File > Open` and `Source 1.0 Map Files (*.vmf)`.
Save the raw result to `ROOT/content/dota_addons/<addon>/maps/<snapshot>_raw.vmap`
and use a working copy for repairs. This route accepts a VMF, not a BSP.

Inspect the generated files and references for entities, geometry, props,
materials, collision and overlays. A visible prop can resolve to existing Source 2
base content; trace its path and hash before crediting asset conversion. A saved
VMAP alone does not establish conversion of every referenced MDL, VMT or PCF.
For individual asset classes, use the internal import actions exposed by this
build's tools/help and retain the actual invocation and outputs.

## Compile and validate

Inspect `addon_compile_content` with `dryRun:true`, then compile using build 2439's
[ResourceCompiler](../resourcecompiler.md).
If the operation does not cover the resource, use the matching editor's recompile
action or verified ResourceCompiler invocation. Keep generated sources and
compiled outputs in the isolated addon.

Reopen representative resources in this build's editors and load a fresh local
map. Check resolved dependencies, collision, animation, particle children and
entity behavior before comparing appearance. Use the common fidelity gates;
report missing assets and restoration of temporary configuration. Preserve the
sources for separately compiling and validating any later target build.
